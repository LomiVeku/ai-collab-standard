# 提议池（可选内容）

> **这份东西不属于 v1.5 规范本体，不改变任何一条条款。**
> 它只是"**冻结期怎么攒意见**"这套机制的完整版本。**看与不看，都不影响你使用那份规范。**

---

## 一、为什么有这个目录

`规范/02-协作规范.md` 的 **C-19** 给了「普适性回流提议」这个通道，`规范/06-填坑备忘录与修订机制.md` 的 **§6.8** 给了「收不收」的判据。

**但这两处都没说：提了以后放在哪，什么时候会被处理。**

作者在自己的项目里用一个叫「提议池」的文件承担这个角色。公开版撤掉内部治理文件时，它一起没了——于是**机制还在，落点空了**。

这个分支补的就是落点。**如果你不需要它，忽略整个目录即可。**

## 二、三份文件

| 文件 | 是什么 |

## 三、这套东西怎么用

**想在自己的项目里也用「冻结 + 池子」这套治理**，建议按这个顺序读：

1. **先读 `02` 的 §三「冻结的边界」**——它把"能改什么"写成可判定的。关键是那条**字面自伤检验**：

   > 把该条款**按字面执行一遍**，看它会不会产生**与该条款自身声明的目的相反**的结果——会 → 错误，修；不会、只是少说 → 不足，不修。

   为什么用它而不用"说的和想的不一致"：后者依赖"起草者当初怎么想"，**第三方复核时意图不可得**，判据无法执行。

2. **再看 `01` 的格式与三条纪律**——**一行一条、不许写分析**。这是防"提议变成长篇意见书"的：一旦允许写分析，池子就会变成另一个规范。

3. **最后看 `02` 的 §五 解冻条件**——四条都是**可观察**的，不靠"感觉差不多了"。

**只是想说点什么？** 开个 issue 就行，不必照这套格式。

## 四、当前状态（截至 2026-10-26）

- 池内 **12 条**
- 解冻条件①要求：**≥15 条**，且至少 **3 条来自不同项目**
- **两个都没满足** —— 12 < 15，且 12 条**全部来自同一个项目**
### 「全部来自同一个项目」不是缺陷，是设计

**只适用于单个项目的东西，本来就不该进通用规范。**

一份只在 A 项目里成立的规则，对 B 项目可能是负担。所以池子里单项目的条目**不构成「普适性证据」**——它们只是候选项。

**什么时候才算证据？** 当**另一个项目独立地**撞上同一个问题时。那说明这个坑不属于某个项目。

这正是条件②：**同一类问题在 ≥2 个独立项目重复出现**。

**它比条件①更硬，也更难凑。条件①是量的门槛，条件②才是质的门槛。**

⇒ 所以：**规范不会因为「又攒了几条」就解冻。** 单项目再怎么攒，也攒不出另一个项目的经验。

**这个数字是故意放在这里的**：它比任何「我们很克制」的表态都更能说明状态。

## 五、一句提醒

**这里的东西都是「意见」，不是「条款」。**

池内条目在解冻并经过梳理之前，**没有一条对任何人有约束力**——包括对写它们的人。**未经体验的提议，不会被当成经验。**
