# 07 决策档案（DR 系列）

> 版本 v1.5｜2026-10-20｜适用范围：所有项目｜上位文件：README（铁律）

## 7.1 为什么需要

项目里最容易丢的，不是文件，是**判断的理由**。

一个会话结束，文件还在、结论还在，但"当时为什么选它、放弃了什么、什么情况下它会失效"留不下来。下一个会话接手时，看到的是一个既成事实：它可能沿用，也可能觉得不合理而重新推导——**重新推导就会重新犯错，而且错得同样自信**。

规则可以传承，疤痕不能。新会话读到"时间感知会撒谎"只是一条规则；看过一次真实的时间线错乱（同一段消息里同时出现两个相隔两小时的时间点，而当事人毫无察觉），才知道这条规则在什么手感下生效、该在什么时候拉响它。

**决策档案补的就是这一段。** 它不记录"现在是什么"，也不记录"应该怎么做"，只记录"为什么是这个样子"：

| 记忆类型 | 回答的问题 | 载体 | 典型失效 |
|---|---|---|---|
| 状态 | 现在是什么 | 交接包、版本登记、台账 | 过期未更新 |
| 规则 | 应该怎么做 | 02–05 各章、填坑备忘录 | 知道规则但不知道何时生效 |
| **判断** | **为什么是这样** | **本档案（DR）** | **被重新推导，且推错** |

判断它有没有价值的唯一标准：**下一个人能不能据此做出同一个决定；或者在条件变化时，明确知道该重开哪一条。**

## 7.2 什么算"有分叉的决策"

**DR-01｜收录三条件（满足其一即记）**：

1. **多方案并存**：代价不同，最终择一；
2. **结论被证伪或修正**：包括错误的原判本身；
3. **会再遇到**：同类分叉在后续会话或项目中还会出现。

三条的判别口径：假设换一个人、只看结果、不看过程，他会不会做出**不同的选择**？会，说明分叉存在；不会，说明这是唯一路径，不必记录。

同等条件下，**失败案例优先于成功案例**：写对的决定只证明"当时判断正确"，写错的决定才说明"判断会在哪里出错"。成功路径往往有多条，失败形态是有限的，更容易被下一个人识别。

不记：单方案执行、纯技术事实、能从产物直接读出的结果。记了会淹没真正需要复用的判断。

**与 06 章的分界**：06 记"发生了什么、怎么修的"；如果"怎么修"经历过方案择一，那个选择记入本档案。同一个事件可以在两处出现，但**各记各的层，不复制原文**。

## 7.3 一条决策的字段集与状态门禁

**DR-02｜字段集（十项）与状态门禁**：

| 字段 | 要写什么 | 缺了会怎样 |
|---|---|---|
| 日期 | **决策日**；补记须另注记录日 | 无法判断它依据的是哪一版事实 |
| 状态 | 待验证 / 有效 / 已推翻 / 被取代 → DR-XXX | 下一个人不知道还能不能引用 |
| 决策人 | **谁最终拍的板**（不是"团队"） | 集体决定 = 没人负责 |
| 背景 | 走到这个分叉的必要事实 | 后人无法判断前提是否还成立 |
| 选项与代价 | A / B / C 各自代价 | 看起来像唯一解，失去复用价值 |
| 决策 | 选了哪个 | — |
| 理由 | 为什么是它、**为什么不是别的** | 只剩余结论，无法在新条件下迁移 |
| 结果与验证 | 实际发生了什么，验证到哪一步 | 无法区分"预计"与"已证实" |
| 证据指针 | 命令输出 / 哈希 / 文件路径 / 条号 | 结论不可复核，等于自述 |
| 失效条件 | 什么情况下需重开 | 旧决策被无限期沿用 |

**状态门禁**：字段完整性是状态的前提，不是"一次写完"的要求。

- **入库最小集**（状态必须为 `待验证`）：日期、背景、选项与代价、决策、理由；
- **转 `有效` 前必须补齐**：决策人、结果与验证、证据指针、失效条件。

理由：决策往往先拍板、后验证。用两档入库，既不逼人一次写全，也不让半成品被当成定论引用。

**DR-03｜选项必须带代价**：每个被考虑过的选项都要写"它的代价是什么"，不写代价的选项视为**没有真正评估**。
理由：没有代价的选项等于"只有好处"，那不是选项，是愿望。决策的质量取决于放弃的那部分是否被看见。

**DR-04｜理由必须回答"为什么不是别的"**：只写"因为 B 更好"不合格；要写清 A 和 C 在什么条件下会更优、为什么当前条件不成立。
理由：这是决策档案与会议纪要的分界线。

**DR-05｜证据指针必须可复核**：写到"打开哪个文件、跑哪条命令、看哪个哈希/条号"就能验证的程度。
**路径写完整路径，不写裸文件名**——同名文件在不同目录会产生歧义（典型案例：同一目录下两个文件，一个带目录前缀、一个没带，导致后者被误报"不存在"）。
反例：`见聊天记录`、`已验证`、`当时测过`、`大家都同意`、`见 read-x.txt`。
理由：不可复核的证据不是证据，只是回忆；回忆会随会话消失。

**DR-06｜失效条件必须可判定**：写成"当 X 出现时重开"，而不是"视情况而定"。
落地：写不出失效条件，先回看**背景与理由**是否成立——决策若连适用条件都说不清，多半是前提没想清；若确属选项未评估，再回到 DR-03 补代价分析。

## 7.4 维护规则

**DR-07｜append-only，不删除**：被推翻的条目保留原文，只改状态、补推翻理由；被新决策取代的，写"被取代 → DR-XXX"。
理由：**错误原判是档案里最有价值的部分**。删掉它，等于把"这条路走过、走错了"也一起删掉。（编号保留与取代标注的通用规则见 01 章 1.6 与 06 章 M-06，此处不重复。）

**DR-08｜当场写；补记必须标注**：决策发生时即写"背景 + 选项与代价"；拍板方补"决策 + 理由"；验证后补"结果"。
事后补记必须标 **「补记」**，并另注记录日。理由：事后写的决策会自动美化——人会把当时的犹豫整理成"经过充分考虑"，把运气整理成判断。

**DR-09｜编号与引用**：`DR-001` 起，按时间递增；跨文件引用写全编号（如"见 DR-003"），不写"见上文"。
**`DR-` 前缀不得与 04 章的交付 `D-xx` 混用**；编号的连续性、不复用、不重排，按 01 章 1.6 执行。项目若已有编号体系，可在适配表登记映射，但档案内必须唯一。

> **篇幅**：一条不超过一屏；长分析留在原始报告里，档案只放结论与指针（与 06 章 M-02 的外链原则一致）。

## 7.5 与交接、协作的接口

**DR-10｜未记录不得援引为"已确认"**：没有进入决策档案的决定，在后续被沿用时**不得写成"已确认"**；若继续沿用，必须补记，并标注"原判定早于补记"。
理由：这条给"不留痕"标一个**可观察的后果**，而不是道德要求。它同时保护接手方——不必为上一任的隐形决定背锅，也不能借"没记录"随意推翻已发生的事实。

**DR-11｜交接必须携带未闭环决策索引**：交接包列出**本批新增/变更的决策编号 + 状态**，不搬运全文；接手方先读索引，按需展开。该索引是 C-14 规定的交接包五样之一。
理由：全量搬运会让交接包膨胀到没人读；只给编号又不给索引，等于没交接。

**DR-12｜事实可被任何人复核，结论归属拍板人**：任何人发现证据指针失效、数据过时、前提改变，应标注 **「证据失效」** 并通知决策人，**不得直接改结论**；是否重开由决策人裁定。
理由：把"复核事实"和"推翻结论"分开，既保护档案不被随意改写，也防止证据腐烂后无人发现。

## 7.6 常见反模式

| 反模式 | 表现 | 对应条款 |
|---|---|---|
| 日记化 | 每件事都记，档案变成流水账 | DR-01 |
| 降标防盗 | 为免责把没有分叉的选择也登记——同样是日记化，判别用 DR-01，不靠 DR-10 的后果兜底 | DR-01 |
| 结论化 | 只写"选 B"，不写放弃的 A、C 及其代价 | DR-03 / DR-04 |
| 事后美化 | 把当时的错判写成"经过充分考虑" | DR-08 |
| 无失效条件 | 写成永久真理，条件变了仍在沿用 | DR-06 |
| 无证据 | 只写"已验证"，指不回任何文件或命令 | DR-05 |
| 复制规则 | 把规则原文抄进决策，两处各自漂移 | 7.1 分工 / M-01 |
| 集体署名 | 决策人写"团队"，出问题无人可追 | DR-02 |

## 7.7 模板

```markdown
## DR-XXX｜一句话标题

- **决策日**：YYYY-MM-DD（补记另注记录日）
- **状态**：待验证 / 有效 / 已推翻 / 被取代 → DR-XXX
- **决策人**：谁最终拍板
- **背景**：为什么会走到这个分叉（只写必要事实）
- **选项与代价**：
  - A. ……——代价：……
  - B. ……——代价：……
- **决策**：选了哪个
- **理由**：为什么是它；A / B 在什么条件下会更优，为何当前不成立
- **结果与验证**：实际发生了什么，验证到哪一步
- **证据指针**：命令输出 / 哈希 / 文件路径 / 条款号
- **失效条件**：出现什么情况时重开
```

> 状态为 `待验证` 时，**决策人、结果与验证、证据指针、失效条件可暂留空**；转 `有效` 前必须补齐（DR-02 状态门禁）。模板列全十项，是为了让"最终要有什么"一眼可见，不是要求一次写完。

## 7.8 项目内落位与示例

每个项目在 `docs/决策记录.md` 建**实例**（编号、内容随项目），本规范只规定方法与底线。项目启动时（README 场景 A）建空骨架 + 索引表；每批收尾时补齐本批决策（DR-02 的字段与状态门禁）。

实例参考：`示例/决策记录-待办提醒窗-20261019.md`——该项目用三个真实分叉（含一个失败案例）做了种子，可直接对照格式与颗粒度。

> **示例不具规范效力**：它只是颗粒度参照；字段冲突时以 7.7 模板为准，状态与结论以项目自身档案为准。示例随规范同步更新。
